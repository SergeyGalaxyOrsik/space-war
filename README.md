# Space War

Многопользовательский пиксельный космический шутер в реальном времени. Игроки выбирают комнату (или создают свою, публичную или с паролем) и вместе отбиваются от волн противника. На каждой пятой волне прилетает флагман. Ещё у каждой комнаты есть общая эмблема 16×16, которую рисуют все одновременно.

Клиент написан на чистом JavaScript (ES-модули, Canvas, Web Audio), без фреймворков и сборщиков. Сервер работает на Node.js: `node:http`, библиотека `ws` и встроенный `node:sqlite`.

## Запуск

Нужен Node.js 22.13 или новее.

    npm install
    npm start          # http://localhost:3000

Порт задаётся через `PORT`, путь к базе — через `DB_FILE` (по умолчанию `data/game.db`).

Тесты:

    npm test

Через Docker:

    docker build -t space-war .
    docker run -p 3000:3000 -v space-war-data:/data space-war

## Управление

- Движение — стрелки или WASD, огонь — пробел или J.
- На телефоне корабль летит за пальцем и стреляет, пока палец на экране. Кнопка в правом нижнем углу поля открывает его на весь экран.
- Эмблема: левая кнопка мыши рисует, правая работает как пипетка.

## Комнаты

- В лобби видны все комнаты с числом игроков и текущей волной. «Общий сектор» есть всегда.
- Комнату можно создать публичной или приватной. Пароль приватной комнаты хранится только в виде хеша scrypt с солью.
- В приватную комнату пускают по паролю. После первого входа сервер запоминает пилота, и переподключение или повторный вход проходят без пароля.
- У каждой комнаты свой мир, эмблема и таблица рекордов. Ссылка вида `https://…/#room=<id>` открывает комнату сразу.
- Комнаты, в которые никто не заходил 7 дней, удаляются. «Общий сектор» не удаляется никогда.

API: `GET /api/rooms` — список, `POST /api/rooms` `{name, isPrivate, password}` — создание. Вход в комнату происходит в первом сообщении вебсокета: `{t:'hello', token, name, color, room, password}`. При отказе сервер отвечает `{t:'denied', code}`.

## Как выполнены требования

| Требование | Реализация |
|---|---|
| Синхронизация через WebSockets | Сервер авторитетный: клиент отправляет только нажатые клавиши (`{t:'in', s, k}`), сервер 30 раз в секунду считает мир каждой комнаты и рассылает снимок её участникам. Свой корабль клиент двигает сразу (предсказание по общей функции `shared/physics.js`) и сверяет с подтверждённым номером ввода. Чужие объекты интерполируются между снимками. |
| Только JavaScript, без фреймворков | `public/` — HTML, CSS и ES-модули, `server/` — чистый Node.js. Единственная зависимость — `ws`. |
| Сохранение между запусками | SQLite (`server/store.js`): комнаты, мир каждой комнаты (волна, враги, бонусы, счётчики), эмблема, состояние пилота в каждой комнате и рекорды. Мир сохраняется каждые 2 с и при остановке. После перезапуска сервер продолжает с того же места. |
| Конкурентный доступ | **Эмблема:** каждая клетка — LWW-регистр с меткой `(часы Лэмпорта, id автора)` (`shared/emblem.js`). Результат не зависит от порядка доставки правок, все участники сходятся к одной картинке. Проигравшая правка возвращается автору с версией победителя, интерфейс показывает, кто перекрасил клетку. **Бонус**, который задели двое в одном тике, достаётся ближайшему кораблю, при равенстве — меньшему id. **Враг**, в которого попали двое: убийство засчитывается первой пуле, остальные получают «помощь» (¼ очков). |
| Потеря соединения | Клиент замечает обрыв по `close`, по событию `offline` и по сторожевому таймеру (нет сообщений 4 с). Затем переподключается в ту же комнату с экспоненциальной задержкой. Корабль ждёт на сервере 90 с как «призрак», дальше его состояние лежит в БД, так что по токену пилот возвращается с теми же очками, позицией и оружием. Последний кадр, список игроков и очередь правок эмблемы хранятся в `localStorage` отдельно для каждой комнаты: без связи видно последнее состояние и можно рисовать, правки уйдут после переподключения. |
| Хостинг | Docker-образ (`Dockerfile`), деплой через Dokploy (см. ниже). |

## Деплой через Dokploy

1. DNS: A-запись домена (например, `space-war.example.com`) на IP сервера.
2. Dokploy → Projects → Create Project → Create Service → **Application**.
3. Provider: GitHub (`SergeyGalaxyOrsik/space-war`, ветка `main`) или Git с URL репозитория.
4. Build Type: **Dockerfile**, путь `Dockerfile`. Переменные окружения не нужны: `PORT=3000` и `DB_FILE=/data/game.db` заданы в образе.
5. Advanced → Volumes → **Volume Mount** (именованный том, не Bind Mount): имя `space-war-data`, путь `/data`. Сервер в контейнере работает от пользователя `node`, именованный том получит правильного владельца автоматически.
6. Domains → Add Domain: хост, путь `/`, Container Port `3000`, HTTPS с Let's Encrypt. Traefik пропускает WebSocket без дополнительной настройки.
7. Deploy. В логах должна появиться строка `Space War: http://localhost:3000`, а `https://<домен>/health` вернуть `{"ok":true,...}`.

Чтобы каждый `git push` выкатывался сам, включи Auto Deploy в Dokploy.

## Структура

    server/index.js        HTTP-статика, API комнат, WebSocket, игровой цикл, heartbeat
    server/rooms.js        комнаты: создание, пароли, доступ, загрузка и выгрузка миров
    server/game.js         мир одной комнаты: волны, столкновения, разрешение конфликтов
    server/store.js        SQLite: комнаты, миры, пилоты, рекорды, миграция со старой схемы
    public/js/shared/      код, общий для клиента и сервера (константы, физика, эмблема)
    public/js/main.js      лобби, вход и выход из комнат, полный экран, игровой цикл
    public/js/net.js       соединение с переподключением
    public/js/world.js     буфер снимков, интерполяция, предсказание
    public/js/render.js    отрисовка, частицы, HUD
    public/js/emblem-editor.js  общий редактор эмблемы с офлайн-очередью
    test/                  node:test — комнаты, конфликты, восстановление, сохранение, интеграция по WebSocket
