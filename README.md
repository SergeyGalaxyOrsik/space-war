# Pixel Squadron

Многопользовательский пиксельный космический шутер в реальном времени. Игроки вместе отбиваются от волн противника, на каждой пятой волне прилетает флагман. Ещё у эскадрильи есть общая эмблема 16×16, которую рисуют все одновременно.

Клиент написан на чистом JavaScript (ES-модули, Canvas, Web Audio), без фреймворков и сборщиков. Сервер работает на Node.js: `node:http`, библиотека `ws` и встроенный `node:sqlite`.

## Запуск

Нужен Node.js 22.13 или новее.

    npm install
    npm start          # http://localhost:3000

Порт задаётся через `PORT`, путь к базе — через `DB_FILE` (по умолчанию `data/game.db`).

Тесты:

    npm test

Через Docker:

    docker build -t pixel-squadron .
    docker run -p 3000:3000 -v pss-data:/data pixel-squadron

## Управление

- Движение — стрелки или WASD, огонь — пробел или J.
- На телефоне корабль летит за пальцем и стреляет, пока палец на экране.
- Эмблема: левая кнопка мыши рисует, правая работает как пипетка.

## Как выполнены требования

| Требование | Реализация |
|---|---|
| Синхронизация через WebSockets | Сервер авторитетный: клиент отправляет только нажатые клавиши (`{t:'in', s, k}`), сервер 30 раз в секунду считает мир и рассылает снимок всем. Свой корабль клиент двигает сразу (предсказание по общей функции `shared/physics.js`) и сверяет с подтверждённым номером ввода. Чужие объекты интерполируются между снимками. |
| Только JavaScript, без фреймворков | `public/` — HTML, CSS и ES-модули, `server/` — чистый Node.js. Единственная зависимость — `ws`. |
| Сохранение между запусками | SQLite (`server/store.js`): каждые 2 с и при остановке сохраняются мир (волна, враги, бонусы, счётчики), эмблема и состояние каждого пилота. Забеги пишутся в таблицу рекордов. После перезапуска сервер продолжает с того же места. |
| Конкурентный доступ | **Эмблема:** каждая клетка — LWW-регистр с меткой `(часы Лэмпорта, id автора)` (`shared/emblem.js`). Результат не зависит от порядка доставки правок, все участники сходятся к одной картинке. Проигравшая правка возвращается автору с версией победителя, интерфейс показывает, кто перекрасил клетку. **Бонус**, который задели двое в одном тике, достаётся ближайшему кораблю, при равенстве — меньшему id. **Враг**, в которого попали двое: убийство засчитывается первой пуле, остальные получают «помощь» (¼ очков). |
| Потеря соединения | Клиент замечает обрыв по `close`, по событию `offline` и по сторожевому таймеру (нет сообщений 4 с). Затем переподключается с экспоненциальной задержкой. Корабль ждёт на сервере 90 с как «призрак», дальше его состояние лежит в БД, так что по токену пилот возвращается с теми же очками, позицией и оружием. Последний кадр, список игроков и очередь правок эмблемы хранятся в `localStorage`: без связи видно последнее состояние и можно рисовать, правки уйдут после переподключения. |
| Хостинг | Клиент — на Vercel (`vercel.json`), игровой сервер — в Docker на Render/Railway/Fly (`Dockerfile`, `render.yaml`). См. «Деплой». |

## Деплой

Vercel запускает только статику и serverless-функции: держать открытые WebSocket-соединения и игровой цикл он не может, файловая система там временная. Поэтому приложение разнесено на две части.

**1. Игровой сервер** — любой хостинг с постоянно работающим процессом и Docker:

- **Render:** New → Blueprint → этот репозиторий. `render.yaml` поднимет Docker-сервис с диском `/data` для SQLite. Диск есть только на платном плане; на `plan: free` без блока `disk` база сбрасывается при редеплое.
- **Railway / Fly.io / VPS:** собрать `Dockerfile`, примонтировать постоянный том в `/data`.

Проверка: `https://<сервер>/health` → `{"ok":true,...}`. Сервер сам отдаёт и клиент, так что одного этого шага уже хватает для игры.

**2. Фронтенд на Vercel:**

1. Vercel → Add New → Project → импортировать репозиторий (настройки берутся из `vercel.json`: без фреймворка, сборка `node scripts/write-config.js`, каталог `public`).
2. Settings → Environment Variables: `GAME_SERVER_URL=https://<адрес игрового сервера>`.
3. Deploy. Скрипт сборки запишет адрес в `public/config.js`, клиент подключится к `wss://<сервер>/ws`.

Или из консоли: `npx vercel --prod -e GAME_SERVER_URL=https://...` (переменную лучше задать в настройках проекта, чтобы она работала при каждом деплое).

## Структура

    scripts/write-config.js  сборка для Vercel: адрес сервера → public/config.js
    server/index.js        HTTP-статика, WebSocket, игровой цикл, heartbeat
    server/game.js         симуляция мира, волны, столкновения, разрешение конфликтов
    server/store.js        SQLite: мир, пилоты, рекорды
    public/js/shared/      код, общий для клиента и сервера (константы, физика, эмблема)
    public/js/net.js       соединение с переподключением
    public/js/world.js     буфер снимков, интерполяция, предсказание
    public/js/render.js    отрисовка, частицы, HUD
    public/js/emblem-editor.js  общий редактор эмблемы с офлайн-очередью
    test/                  node:test — конфликты, восстановление, сохранение, интеграция по WebSocket
